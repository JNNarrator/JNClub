## 二、M1 · 音乐体验增强

### M1-1 歌单管理（Playlist）

**后端（jnclub-module-music）**
- 新增表（幂等 `CREATE TABLE IF NOT EXISTS`，追加到 `schema.sql`）：
  - `music_playlist`：`id / device_id / name / created_at / updated_at`
  - `music_playlist_item`：`id / playlist_id / track_id / position / created_at`，`UNIQUE(playlist_id, track_id)`
- 新接口（延续匿名 `X-Device-Id` 隔离，前缀 `/music/api/v1/playlists`）：
  - `GET /api/v1/playlists` — 歌单列表（含曲目数）
  - `POST /api/v1/playlists` — 新建 `{ name }`
  - `PUT /api/v1/playlists/{id}` — 重命名
  - `DELETE /api/v1/playlists/{id}` — 删除歌单（级联删 item）
  - `GET /api/v1/playlists/{id}/tracks` — 歌单曲目
  - `POST /api/v1/playlists/{id}/tracks` — 添加曲目 `{ trackId, position? }`（幂等去重）
  - `DELETE /api/v1/playlists/{id}/tracks/{trackId}` — 移除曲目
  - `PUT /api/v1/playlists/{id}/tracks/sort` — 歌单内排序（可选，P2）
- 涉及文件：新增 `PlaylistApi`、`PlaylistController`、`PlaylistService(+Impl)`、`Playlist`、`PlaylistItem` 实体与 Mapper；`schema.sql` 追加 DDL。

**前端（music-frontend）**
- `ui.ts` 增加 `showPlaylistPanel` 或独立视图状态；`PlayerBar` / `TrackList` 增加「加入歌单」入口。
- 新增 `PlaylistPanel.vue`：歌单列表（新建/重命名/删除）、点歌单展开曲目（点击播放、移除、加入当前队列）。
- 新建歌单弹层：输入名称 → `POST /playlists` → 添加当前曲目。

### M1-2 跨设备播放进度同步

**后端**
- `music_play_history` 增加列：`progress_seconds INT DEFAULT 0`、`updated_at DATETIME`（幂等迁移：`ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 或按 `information_schema.COLUMNS` 判断）。
- `POST /api/v1/history` 请求体扩展 `{ trackId, progress? }`，写入时更新 `played_at + progress_seconds + updated_at`。
- 新接口 `GET /api/v1/history/latest`：返回最近一条 `{ trackId, progressSeconds, playedAt }`，供前端启动「继续播放」。
- 涉及文件：`PlayHistory` 域对象、`HistoryService(Impl)`、`HistoryApi`、`schema.sql`。

**前端**
- `player.ts`：切歌时（`playIndex`）上报上一曲进度；`timeupdate` 节流（如每 15s）上报当前曲进度；暂停/结束上报一次。
- 初始化：`PlayerPage` / `App.vue` onMounted 拉取 `history/latest`，若 `progressSeconds > 30` 且有可播放直链，在队列末尾追加该曲并提示「继续上次播放」（不自动打断当前列表，避免反直觉）。
- 上报失败静默，不阻塞播放。

### M1-3 猜你喜欢 / 每日推荐

- 新接口 `GET /api/v1/recommend?limit=20`：
  - 规则（无需新表）：用户收藏曲目 → 按播放历史频率补齐 → 随机补足到 limit；无数据时返回随机曲目。
  - 复用现有 `FavoriteService` / `HistoryService` / `TrackApi` 数据源。
- 前端 `TrackList` 或新 `RecommendSection.vue`：入口「猜你喜欢」，点歌曲直接加入队列播放。

## 三、M2 · 浏览器扩展增强

### M2-1 一键稍后读
- `lib/api.js`：`createBookmark` 支持 `readLater` 透传（body `readLater: 1`）。
- `popup/popup.html + popup.js`：收藏区增加「存为稍后读」复选框（默认关，记忆上次选择到 storage）；保存时 body 带 `readLater`。
- `background/service-worker.js`：右键菜单新增「保存为稍后读」：直接 `POST /api/bookmarks { title, url, directoryId, readLater: 1 }`（目录用 `defaultDirId`），成功后 notifications 提示。

### M2-2 剪藏网页快照
- `lib/api.js`：新增 `captureSnapshot(bookmarkId)` → `POST /api/snapshots/{bookmarkId}`。
- `popup.js`：收藏成功后若勾选「保存网页快照」，调用 `captureSnapshot`；状态区显示「已收藏 ✓ · 快照已保存/快照失败（可稍后在 Web 端重试）」。
- 与 M2-1 合并为一个「保存选项」区：`[x] 存为稍后读  [x] 保存网页快照`（记忆偏好）。

### M2-3 保存前去重提示
- 复用 batch 页的 `normalizeUrl`（提取到 `lib/api.js` 或新 `lib/urls.js` 共享）。
- `popup.js` 保存前：`fetchBookmarks(directoryId)` 拉取目标目录收藏，`normalizeUrl` 比对；命中重复时弹窗/内联提示「该链接已收藏，仍要保存吗？」（继续 / 取消）。
- 数据量保护：仅比对选中目录；目录收藏过多（> 500）时跳过检测（不做全量扫描）。
- batch 页逻辑不动（已有跳过策略）。

### M2-4 扩展元信息
- `manifest.json` version bump `1.1.0 → 1.2.0`，description 同步补充「稍后读 / 网页快照 / 去重提示」。

## 六、风险与边界

1. **匿名设备隔离**：音乐全部接口按 `X-Device-Id` 隔离，歌单/进度同步均为「同设备多端」语义，不做账号级合并（与现有设计一致）。
2. **进度同步不打扰**：恢复播放仅提示不自动播放；上报节流，避免频繁写库。
3. **快照可靠性**：`/api/snapshots/{bookmarkId}` 为服务端抓取，部分站点可能失败；扩展只做「触发 + 提示」，失败不阻断收藏主流程。
4. **去重轻量**：仅比对选中目录，不做全量扫描，避免 popup 卡顿。
5. **兼容性**：`POST /api/v1/history` 旧请求体（无 progress）保持兼容；历史表加列用幂等迁移。
6. **歌单数据规模**：匿名设备歌单不做分页（个人规模有限），但列表接口预留 `limit`。
