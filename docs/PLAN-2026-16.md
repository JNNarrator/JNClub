# JNClub 迭代规划 · 2026-16（体验精修与视觉优化 / UX Polish & Beauty Pass）

> 状态：✅ 已全部实现（前端构建通过，提交 `6107c0a`；16 期验收标准已达成）
> 前置：2026-15 日历 2.0、搜索体验增强、稳定与性能已交付；便签编辑器已修复自定义光标并完成编辑区空间优化。
> 原则：**优化、美化为主，新功能为辅**。不追求大功能堆叠，而是把已经有的模块打磨到「顺手、好看、统一、不卡」。
> 目标：
> - 让各模块的视觉语言、间距、圆角、空态、加载态、交互反馈更统一。
> - 让高频操作更快、更跟手，减少无谓的视觉噪音和点击成本。
> - 只做低成本、高感知的小新功能，作为体验增强的补充。

---

## 一、现状与可优化点

1. **视觉一致性**
   - 已有较完整的设计 token（Apple Pink 玻璃拟态），但仍有少量硬编码品牌色、圆角、阴影散落在组件中。
   - 列表 / 网格 / 卡片 / 弹窗 / 抽屉 / 菜单的空态、加载态、hover/focus/selected 状态风格不完全统一。
   - 滚动条、选区、占位符、焦点环等系统级细节还没有形成统一规范。

2. **信息密度与布局**
   - 各模块页头（标题、筛选、操作按钮）高度和间距不统一。
   - 部分列表/卡片在数据量增大后缺少“紧凑/舒适”密度选项。
   - 便签编辑器已压缩，但只读预览、阅读弹窗仍有排版和聚焦优化空间。

3. **交互手感**
   - 页面切换、弹窗、列表操作缺少一致的轻量动效；动效偏好 `prefers-reduced-motion` 未全覆盖。
   - 键盘操作、焦点可见性、可访问标签仍需统一补强。
   - 通知、保存、上传、搜索等“异步状态”反馈还不够直观。

4. **性能与稳定性**
   - 大列表（云盘、便签、RSS、搜索结果）仍可能随数据量增长而卡顿。
   - 重型组件（md-editor、阅读弹窗、音乐）有进一步懒加载空间。
   - 请求防抖/取消、图片懒加载、通知轮询收敛等可以继续治理。

5. **低成本新功能机会**
   - 全局“最近打开 / 快速新建”入口。
   - 阅读器设置（字号、行距、栏宽、专注模式）。
   - 便签编辑器的轻量快捷插入（表格/引用/双链快速输入）。
   - 待办/日历的快捷筛选和更清晰的时间展示。

## 二、M1 · 视觉系统统一（优化/美化为主）

### M1-1 设计 Token 补全
- 在 `themes/tokens.ts` 中补齐：
  - 统一 `--focus-ring`、`--scrollbar-thumb`、`--scrollbar-track`、`--selection-bg`、`--placeholder`
  - 统一 `--card-hover`、`--card-selected`、`--skeleton-bg`、`--overlay-bg`
  - 统一弹窗/抽屉/菜单/通知面板的玻璃参数（`--glass-panel-bg`、`--glass-panel-border`、`--glass-panel-shadow`）
- 亮/暗双主题同步补充，优先替换高频硬编码。

### M1-2 基础组件状态统一
- 建立共享样式片段或 `base.css`：
  - 卡片：hover 轻浮起 + 边框/阴影过渡
  - 当前项/选中项：统一品牌色左条或背景
  - 禁用态、加载骨架、空态：统一视觉语言
- `EmptyState` 组件已有，补齐“搜索无结果 / 列表为空 / 错误重试”三种场景，并允许传入建议操作按钮。
- 全局滚动条：细、圆角、跟随亮暗主题；内容区滚动条不喧宾夺主。

### M1-3 玻璃拟态与页面背景统一
- 统一 `backdrop-filter` 的 `blur()` 值、面板 `border` 透明度、阴影深浅。
- 主内容区背景径向渐变与玻璃面板叠加后，避免出现“脏白/灰边”。
- 对弹窗、抽屉、下拉、通知中心做一次视觉回归：亮暗主题下文字对比度达标。

### M1-4 图标与品牌细节
- 将散落的品牌硬编码色（如 `CursorTrail`、`CursorClickParticles`、`BrandLogo`）改为引用 token 或保留在主题配置中。
- 统一图标尺寸层级：正文 14/16、操作 16/18、大图标 20/24。
- 统一按钮圆角/高度/内边距：小按钮 26px、中按钮 32px、大按钮 38px。

## 三、M2 · 布局与信息密度优化（优化为主）

### M2-1 全局页面头规范化
- 将各模块页头收口为统一结构：标题 + 副标题/面包屑 + 筛选区 + 主操作区。
- 页头高度保持紧凑（约 52–60px），移动端自动隐藏次要文案。
- 工具栏按钮仅在高频操作保留文字，次要操作折叠到“更多”。

### M2-2 全局密度偏好
- 将已存在的 Dashboard 密度偏好扩展为全局 `ui.density`：
  - `comfortable`（默认）/ `compact`
  - 影响列表行高、卡片 padding、页头间距、表格单元格。
- 持久化到现有用户偏好，恢复默认可重置。

### M2-3 列表 / 网格 / 表格
- 统一列表行高：普通 40px、紧凑 32px；卡片间距：普通 16px、紧凑 8px。
- 大列表增加“列表 / 网格”切换一致性；移动端默认列表或单列卡片。
- 空态不再占满整屏：在容器内居中，尺寸克制。

### M2-4 便签阅读与编辑体验
- 延续已完成的编辑区压缩，继续优化：
  - 只读预览支持“栏宽切换”（窄栏 / 适中 / 全宽）。
  - 编辑态顶部增加“专注模式”开关：隐藏顶栏非必要按钮、只保留标题和保存状态。
  - 预览排版复查：标题层级、代码块、表格、引用在亮暗主题下的对比度。
- 阅读弹窗（ReadingModal）支持字号/行距/主题（跟随系统或独立按钮）。

### M2-5 待办 / 日历信息密度
- 待办行增加更清晰的优先级、日期、重复、子任务进度视觉。
- 日历月视图卡片压缩高度，避免拥挤；周视图时间网格在移动端保留可读性。
- 快速添加框可折叠为一行，减少固定占位。

## 四、M3 · 交互与体验优化（优化为主）

### M3-1 动效统一
- 使用统一时长/缓动变量：`--dur`、`--ease`、`--ease-bouncy`。
- 按钮按压、卡片 hover、弹窗进出、页面切换、列表进入均使用轻量动效。
- 严格遵守 `prefers-reduced-motion`：关闭位移、缩放、粒子等非必要动画。

### M3-2 键盘与可访问性
- 全局焦点可见：所有可交互元素在键盘 Tab 时显示统一 focus ring。
- 弹窗/抽屉：支持 ESC 关闭、打开后聚焦、关闭后还原焦点。
- 列表/搜索：支持方向键导航、Enter 执行、Tab 切换分组。
- 为纯图标按钮补 `aria-label` / `title`。

### M3-3 异步状态反馈
- 保存：统一“保存中/已保存/未保存”反馈样式。
- 上传：统一进度、暂停、失败重试、成功后跳转。
- 搜索：统一 loading、无结果、错误、建议展示。
- 通知：未读项 hover/点击后平滑标记已读，全部已读有轻量成功动画。

### M3-4 右键菜单与弹层
- 统一自绘右键菜单、下拉菜单、浮层的位置计算与点击外部关闭逻辑。
- 浮层阴影/圆角/背景与玻璃面板一致；小屏自动改为底部抽屉样式（可选）。

## 五、M4 · 性能与稳定性优化（优化为主）

- **重型组件懒加载**：`NoteEditor`、`ReadingModal`、`Music` 等按路由/打开时动态导入，降低首屏体积。
- **大列表虚拟滚动**：云盘文件、便签列表、RSS 文章、搜索分组在超过阈值（如 100 条）时启用虚拟滚动或“加载更多”。
- **请求收敛**：搜索/筛选输入统一防抖；发起新请求时取消旧请求（`AbortController`）；重复请求短时间内存缓存。
- **图片懒加载**：收藏 favicon、便签图片、文章缩略图补 `loading="lazy"` 和占位背景。
- **通知轮询**：页面不可见时暂停，`visibilitychange` 恢复；减少无效请求。
- **样式与资源清理**：
  - 删除不再使用的样式类/图片/依赖。
  - 合并重复的玻璃、卡片、空态样式到共享层。
  - 构建产物复查 chunk 体积，必要时拆分。

## 六、N1 · 低成本新功能（新功能为辅）

### N1-1 全局“最近打开 / 快速新建”
- 在搜索命令面板或顶栏增加“最近打开”列表：最近编辑的便签、最近访问的收藏/文件/待办。
- 快速新建入口：新建便签、新建收藏、新建待办。
- 数据可基于现有接口 + 本地最近记录，不新增复杂后端。

### N1-2 阅读器设置
- ReadingModal 增加字号、行距、栏宽、专注背景。
- 设置写入用户偏好，跨设备同步（走现有偏好接口）。

### N1-3 便签快捷插入
- 在编辑器工具栏/命令面板增加常用 Markdown 快捷插入：引用、表格、代码块、双链 `[[ ]]`。
- 不改变现有编辑核心，只做输入增强。

### N1-4 待办快捷筛选增强
- 待办页增加“明天 / 本周 / 无日期”快捷筛选（若已有，则只做交互/样式统一）。
- 日历与待办互相跳转保留高亮定位。

## 七、排期建议

| 里程碑 | 主题 | 优先级 |
| --- | --- | --- |
| M1 | 视觉系统统一 | P0 |
| M2 | 布局与信息密度 | P0 |
| M3 | 交互与可访问性 | P1 |

- M3 + M4 可并行/穿插，不阻塞视觉优化交付。
- N1 中“最近打开 / 阅读器设置”可提前做，作为体验增强的“新功能点缀”。

## 十、风险与边界

1. **视觉改造回归**：大量样式调整可能影响现有布局，因此采用“共享样式先行 + 模块逐步套用”，每批构建验证。
2. **全局密度**：不能为了紧凑牺牲触控目标（移动端最小 32px 点击区）。
3. **动效克制**：以轻量为主，避免影响性能；强制支持减少动效偏好。
4. **新功能克制**：N1 只做低成本高感知项，不引入新的复杂后端表/长链路。
