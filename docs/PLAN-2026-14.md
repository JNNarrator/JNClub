# JNClub 功能规划 · 2026-14（待办日历 2.0 + 全局智能搜索 2.0）

> 状态：📋 规划中（尚未开始编码）
> 来源：Dashboard 2.0 交付后，用户选择的两条后续迭代线：**待办与日历 2.0**、**全局智能搜索**。
> 策略：两条线相互独立，可分别排期、分别上线；建议把 A 作为下一迭代，B 紧随其后或并行。
> 目标：让「个人工作台」从「能记录」升级为「会提醒、好查找、快执行」。

---

## A. 待办与日历 2.0

### A1. 现状核实

- 待办：CRUD、优先级（0/1/2）、截止日期、备注、完成状态、完成时间、拖拽排序。
- 页面：TodoView 支持「全部 / 进行中 / 已完成 / 今天 / 逾期」筛选、快速添加、行内完成、撤销删除、打开页面时浏览器通知检查。
- 日历：CalendarView 月视图聚合待办（按截止日）+ 便签（按更新时间），支持跨月逾期置顶、拖拽改期、新建待办。
- Dashboard 2.0 已通过 `alerts` 把「今日到期 / 逾期 / 待办」透出到首页。

### A2. 痛点

1. 没有重复任务：每周/每月固定事项每次都要手动重建。
2. 没有子任务/清单：一件事拆成多步时无法跟踪进度。
3. 提醒太弱：只有打开待办页时检查一次，没有真正的定时站内/浏览器提醒。
4. 日历只有月视图，无法看一周安排；待办只有日期没有时间段。
5. 快速添加仍是表单式，输入不够自然。
6. 缺少完成趋势等轻量统计，无法回答「最近完成情况如何」。

### A3. 功能规划

#### A3-1. 数据模型扩展

- `t_todo` 增加字段（迁移脚本放 `docs/init.sql`）：
  - `due_time`：截止时间（可选，配合 `due_date`）
  - `remind_at`：提醒时间（可选）
  - `recurrence_rule`：重复规则（如 `FREQ=DAILY;INTERVAL=1` 或简化为 `daily/weekly/monthly` + 间隔 JSON）
  - `group_id`：待办分组/清单 ID（可选，兼容现有无分组场景）
- 新增 `t_todo_item`：子任务表
  - `id / todo_id / user_id / title / completed / sort_order / create_time / update_time`
- 新增 `t_todo_group`（可选）：清单分组，如「工作 / 生活 / 学习」。

#### A3-2. 重复任务

- 支持每日、每工作日、每周、每月、每年，并以“动态展开”为主：
  - 不提前落所有未来实例；查询某日期范围时按规则计算应出现的实例。
  - 完成当前实例后按规则推进下一次 `due_date`。
- 编辑时支持「仅本次」「修改整个系列」。
- Dashboard 今日必办与统计只计算当前应做实例。

#### A3-3. 子任务 / 清单

- 待办详情可展开子任务：新增、勾选、删除、拖拽排序。
- 父待办显示 `已完成子项 / 总子项` 进度。
- 全部子任务完成时可自动完成父待办（可配置为手动）。

#### A3-4. 提醒

- 后端定时任务（如每分钟）扫描 `remind_at <= now && completed=0 && 未通知`。
- 通知渠道：
  - 站内通知：新增 `t_notification` 或复用现有通知能力（如无则新增）。
  - 浏览器通知：前端订阅/轮询后使用 `Notification API`。
  - 可选：Web Push / 邮件，本期可只做站内 + 浏览器通知。
- Dashboard 和全局搜索中也能看到待提醒事项。

#### A3-5. 日历增强

- 视图：
  - 保留月视图。
  - 新增周视图（时间网格）和「日程列表」。
- 待办支持时间段：
  - `due_date + due_time` 作为开始时间，新增 `end_time` 作为结束时间（或仅用时长）。
- 交互：
  - 周视图拖拽新建、拖拽改期、拖拽调整时长。
  - 月视图保留现有拖拽改期、新建待办。
- 日历继续聚合便签（最近编辑）和稍后读（截止/阅读日期，如有）。

#### A3-6. 自然语言快速添加

- 在 TodoView 快速输入框中支持自然语言：
  - `周五 14:00 准备周报`
  - `每天 9:00 站会`
  - `今晚 回复邮件`
- 解析规则先做中文/数字时间的基础版，解析失败时退化为普通标题。

#### A3-7. 智能清单与统计

- 智能筛选：
  - 今天 / 明天 / 本周 / 已逾期 / 无日期 / 高优先级
  - 按清单分组（`group_id`）
- 统计：
  - 近 7/30 天完成趋势
  - 当前逾期数、今日应完成数
  - 可在 Dashboard 趋势或待办页顶部展示。

### A4. 涉及文件（预测）

- 后端：
  - `entity/Todo.java`、新增 `entity/TodoItem.java`
  - `mapper/TodoItemMapper.java`
  - `service/TodoService.java`、新增 `TodoItemService.java`
  - `service/CalendarService.java`
  - `controller/TodoController.java`、`CalendarController.java`
  - 新增提醒扫描 `ReminderService.java`
  - `docs/init.sql` 迁移脚本
- 前端：
  - `TodoView.vue`：清单、重复、提醒、自然语言、智能筛选、统计
  - `CalendarView.vue`：周视图、时间网格、拖拽交互
  - 共享组件：`JNotificationToast` 等（如需要）

## B. 全局智能搜索 2.0

### B1. 现状核实

- 后端 `SearchService` 已跨模块搜索：收藏（标题+URL）、便签（标题+Markdown 内容+摘要）、云盘（文件名）、密码库（非密文字段）、标签、音乐曲目。
- 支持多关键词 AND 匹配、高亮区间、结果分组。
- 前端 `SearchDrawer` 已支持 `Ctrl/Cmd+K`、搜索历史（localStorage）、快捷命令、键盘上下选择/Enter 执行/类别跳转。

### B2. 痛点

1. 数据源不全：**待办、稍后读、RSS/订阅文章**还没有进入搜索结果。
2. 排序粗糙：纯 `LIKE`，没有“标题命中 > 内容命中 > 最近更新”的相关度加权。
3. 交互不够快：结果只能跳模块，不能直接打开收藏 URL / 下载文件 / 编辑便签 / 跳转待办。
4. 缺少搜索语法：不能快速按 `type:` / `#标签` / `date:` 过滤。
5. 搜索历史本地存储，换设备不共享；没有建议词（suggest）。
6. 没有对文章/文本文件内容搜索（本期可只做 RSS/便签内容）。

### B3. 功能规划

#### B3-1. 数据源扩展

- `SearchService.search()` 新增分组：
  - `todos`：标题 + 备注
  - `readLater`：稍后读书签标题 + URL + 进度
  - `feeds`：RSS 订阅源名称
  - `feedItems`：RSS 文章标题 + 内容摘要（可限制只搜未读/最近 90 天）
- 返回结构保持兼容，前端新增分组渲染。

#### B3-2. 相关度排序

- 轻量评分，不引入 Elasticsearch：
  - 标题前缀命中 + 10
  - 标题包含 + 6
  - 内容/URL/备注命中 + 3
  - 最近更新加权（7 天内 + 2，30 天内 + 1）
- 各模块分别取 Top N 后统一按分数展示，也可按类型分组内排序。
- 多关键词仍保持 AND，但放宽为“标题必须命中一个词，其他词可命中任一字段”。

#### B3-3. 搜索语法与过滤

- 支持自然前缀：
  - `#标签名` → 只搜标签
  - `type:todo` / `type:note` / `type:bookmark` / `type:file` / `type:vault` / `type:feed` / `type:track`
  - `date:today|week|month` 或 `date:2026-08` → 按创建/更新时间过滤
- 前端在输入框下方显示当前解析出的过滤条件，可一键清除。

#### B3-4. 结果直达

- 收藏：直接新窗口打开 URL；`Shift+Enter` 新开。
- 便签：直接打开编辑/预览页。
- 云盘：直接触发下载。
- 密码库：跳转到对应密码条目（但不展示密文）。
- 待办：跳转待办页并高亮该条。
- RSS 文章：打开订阅页并定位文章（或直接打开详情）。

#### B3-5. 历史与建议

- 搜索历史从 localStorage 升级为服务端保存（可使用 `user_preferences` 或新增 `t_search_history`）。
- 新增 `GET /api/search/suggest?keyword=`：
  - 返回热词/历史/快捷命令/模块提示。
  - 前端空输入时显示最近使用与推荐命令。
- 清空历史入口保留。

#### B3-6. 前端交互升级

- SearchDrawer 增加类型筛选 Chips（全部 / 收藏 / 便签 / 文件 / 密码库 / 待办 / 订阅 / 音乐）。
- 结果行增加类型图标、时间、摘要、高亮和「打开 / 下载 / 前往」动作。
- 键盘：
  - `Tab` 切换分组
  - `Enter` 默认动作
  - `Shift+Enter` 收藏在新标签打开
- 空态与无结果提示统一使用现有 `JEmptyState`。

### B4. 涉及文件（预测）

- 后端：
  - `service/SearchService.java`
  - `controller/SearchController.java`
  - 新增 `SearchHistoryService` 或复用 `UserPreference`
  - `TodoMapper / FeedItemMapper` 查询接入
- 前端：
  - `SearchDrawer.vue`
  - `useSearchActions.ts`
  - 各模块跳转/高亮逻辑
  - 新增类型筛选与搜索语法解析 composable

## C. 里程碑建议

| 里程碑 | 范围 | 说明 |
| --- | --- | --- |
| M1（A 核心） | 待办模型扩展、子任务、重复任务、提醒、智能筛选 | 先补“会提醒、能拆解”的骨架 |
| M2（A 日历） | 周视图、时间段、拖拽交互、自然语言添加 | 依赖 M1 的数据模型 |
| M3（B 核心） | 搜索数据源扩展、相关度排序、结果直达 | 可独立上线 |
| M4（B 体验） | 搜索语法、服务端历史、建议词、类型筛选 | 依赖 M3 |

- 若希望快速见效：先做 M3，搜索扩展改动小、收益直接。
- 若希望整体体验连贯：先做 M1→M2，再接 M3→M4。

## D. 风险与边界

1. **数据迁移**：`t_todo` 增加字段与 `t_todo_item` 建表需在 `docs/init.sql` 增加幂等迁移脚本；线上需执行迁移。
2. **重复任务策略**：动态展开能避免大量未来实例，但规则解析和“完成本次/整个系列”需要清晰设计，避免数据重复。
3. **搜索性能**：仍走 MySQL `LIKE`，数据量大后可考虑 `FULLTEXT`；本期不引入 Elasticsearch。
4. **隐私**：密码库搜索只搜名称/账号/站点/备注，永不触碰密文；搜索结果不展示密码。
5. **通知依赖**：浏览器通知需要用户授权，未授权时降级为站内提醒/页面红点。
6. **自然语言解析**：中文时间解析可能不准，先做规则版，解析失败退化为普通标题。
