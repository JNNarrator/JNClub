## 现状核实（规划前结论）

- **阅读模式已存在**：`GET /api/bookmarks/read`（jsoup 服务端正文提取+清洗），前端 `ReadingModal.vue`；但无「稍后读」状态、无阅读进度跟踪。

- **待办已具备日期字段**：`t_todo.due_date / priority / completed / completed_at`，`GET /api/todos?filter=` 已支持 today/overdue；无日历视图。
- **分享已具备基础**：`t_share`（token/refType/refId/passwordHash/expiresAt），密码 + 有效期已有；缺访问统计（PV）、我的分享全列表、Markdown/PDF 导出。

- **迁移模式**：沿用 `NoteTableInit`（ApplicationRunner + `ensureColumn` + `CREATE TABLE IF NOT EXISTS`），新表/新列零人工迁移。
- **依赖现状**：jsoup ✅、hutool ✅、Rome ❌（需新增）。

## 方向一：效率闭环

### ① 稍后读 + 阅读进度

**目标**：收藏可分「稍后读」标记，阅读模式内实时记录阅读进度，概览页出现「继续阅读」入口。

**后端**
- `t_bookmark` 新增列（复用 NoteTableInit 模式，新 `FeatureTableInit` 类）：
  - `read_later` TINYINT(1) 默认 0 —— 稍后读标记
  - `read_progress` INT 默认 0 —— 阅读进度 0-100
  - `read_at` DATETIME —— 最近阅读时间
- `BookmarkService` 新增：
  - `PUT /api/bookmarks/{id}/read-later` body `{ readLater: bool }`
  - `PUT /api/bookmarks/{id}/progress` body `{ progress: int }`（节流：与库内差值 ≥5 才写，避免高频滚动写库；同时更新 `read_at`）
  - `GET /api/bookmarks/read-later` —— 稍后读列表
- `StatsService.summary()` 增加 `readLater: { count, list: [{id,title,url,progress,readAt}] }`（`read_later=1 && progress<100`，按 `read_at` 倒序取前 N）

**前端**
- 收藏卡片/行/网格：新增「稍后读」图标按钮（BookmarkPlus），选中态高亮
- `ReadingModal.vue`：新增 prop `bookmarkId`，滚动监听计算进度（防抖），关闭时回写进度
- 概览看板：新增「继续阅读」卡片（进度条 + 点击打开阅读模式）
- 收藏夹支持按「稍后读」筛选（复用现有 filter 模式）

**验收**：①收藏可标记/取消稍后读，刷新保持；②阅读模式内滚动 50% 后关闭，卡片进度条显示 50%；③概览「继续阅读」只出现未读完条目且点击可读。

> ✅ 已实施（2026-09-22）：
> - 后端：`FeatureTableInit` 幂等加列 read_later/read_progress/read_at；`BookmarkService` 新增 `setReadLater` / `updateReadProgress`（0-100 截断 + 与库内差值 ≥5 节流 + 读完自动移出稍后读）/ `listReadLater`；`BookmarkController` 新增 `GET /read-later`、`PUT /{id}/read-later`、`PUT /{id}/progress`；`StatsService.summary()` 增加 `readLater`（未读完前 10 + 进度）。
> - 前端：`CollectionCard` 右键菜单 + 下拉菜单加「稍后读/移出稍后读」，卡片显示稍后读徽标 + 阅读进度条；`ReadingModal` 新增 `bookmarkId` prop，滚动跟踪进度（150ms 节流回写 + 关闭时落库）+ 顶部进度条；`Home.vue` 阅读模式传入 bookmarkId；概览「最近动态」新增「继续阅读」面板（进度显示，点击直接打开阅读模式）。
> - 验证：后端 `mvn compile` ✅；前端 `vue-tsc --noEmit` ✅

### ② 网页快照归档

**目标**：收藏时/手动为页面抓取 HTML 快照存 dufs；失效检测命中时「查看快照」兜底阅读——与失效检测形成闭环。

**后端**
- 新表 `t_bookmark_snapshot`（启动幂等自建）：`id / bookmark_id / user_id / dufs_key / title / size / captured_at / deleted`
- 新 `SnapshotService`：
  - `capture(bookmarkId)` —— hutool GET（UA 同失效检测、超时 15s、body 上限 2MB）→ 原始 HTML PUT 到 dufs `/jnclub/snapshots/{userId}/{bookmarkId}.html`（复用 UploadService 的 dufs 写入方式）
  - 幂等：重复抓取覆盖旧快照（同 key），记录 captured_at
  - `get(bookmarkId)` / `has(bookmarkId)`
- `BookmarkController` 新增：
  - `POST /api/snapshots/{bookmarkId}` —— 手动抓取快照
  - `GET /api/snapshots/{bookmarkId}` —— 快照元信息
  - `GET /api/snapshots/{bookmarkId}/content` —— 快照内容（登录鉴权，从 dufs 读，text/html 输出）
  - `DELETE /api/snapshots/{bookmarkId}` —— 删除快照（dufs 对象 + 记录）
- 失效检测联动：`listDeadLinks()` 响应附带 `hasSnapshot`，前端据此显示「查看快照」

**前端**
- 收藏菜单：新增「归档快照」动作（成功 toast）
- `DeadLinkModal.vue`：失效项有快照时显示「查看快照」按钮 → 新 `SnapshotModal.vue`（iframe 渲染快照 HTML，附「打开原文」兜底）
- 收藏卡片显示快照存在标记（小图标）

**验收**：①手动归档后快照可查看、可删除；②失效检测列表中带快照的项出现「查看快照」并能打开；③快照读取需登录（未登录 401）；④dufs 对象随删除清理。

> ✅ 已实施（2026-09-22）：
> - 后端：`FeatureTableInit` 幂等建 `t_bookmark_snapshot`（bookmark_id/user_id/dufs_key/title/url/size/captured_at）；新 `BookmarkSnapshot` 实体 + Mapper；`SnapshotService`（hutool 抓取 ≤2MB 存 dufs `/jnclub/snapshots/{userId}/{bookmarkId}.html` + 元数据入库 + 内容读取 + dufs 删除；重复抓取覆盖旧快照）；`SnapshotController`（`POST/GET/DELETE /api/snapshots/{bookmarkId}` + `GET .../content`，默认登录鉴权）；`BookmarkService.listDeadLinks()` 附带 `hasSnapshot`。
> - 前端：新 `SnapshotModal.vue`（iframe 渲染快照 + 元信息/打开原文/删除/重新加载）；`DeadLinkModal` 失效项「有快照」标签 + 「查看快照」按钮（删除快照后重新检测）；`CollectionCard` 下拉菜单「归档快照/查看快照」+ 卡片快照徽标（点击即看）。
> - 验证：后端 `mvn compile` ✅；前端 `vue-tsc --noEmit` ✅

### ③ 日历视图

**目标**：独立「日历」页，月视图聚合待办（due_date）与便签（create/update 时间），拖拽改期。

**后端**
- 新 `CalendarController` + `CalendarService`：
  - `GET /api/calendar/month?year=2026&month=9` → `{ todos: [{id,title,dueDate,completed,priority}], notes: [{id,title,updateTime,archived}] }`
  - todos：dueDate 落在当月（含跨月 overdue 未完成项置顶标注）
  - notes：updateTime 落在当月（archived=0）
- 拖拽改期：复用 `PUT /api/todos/{id}`（body `{ dueDate }` 已支持）；如缺则补 `PUT /api/todos/{id}/due-date`

**前端**
- 新路由 `/calendar`（挂 MainLayout 壳，参照 TodoLayout）→ `CalendarView.vue`：
  - 月网格（上/下月、回到今天），格子内显示待办（勾选即完成）+ 便签圆点
  - 待办卡片可拖拽到其他日期（HTML5 drag 或 sortablejs，改 dueDate 后刷新）
  - 点空白格子快捷新建待办（dueDate 预填当天）
  - 点便签圆点 → 跳 `/notes/:id`
- `navConfig.ts`：新增 `calendar` NavKey（图标 Calendar，route → /calendar），默认序插在 todos 后；MobileTabBar 视情况加

**验收**：①月视图正确聚合当月待办/便签；②拖拽待办到另一天，刷新后 dueDate 已变；③快捷新建待办默认日期正确；④过期未完成待办在当月有标识。

> ✅ 已实施（2026-09-22）：
> - 后端：新 `CalendarService` + `CalendarController`，`GET /api/calendar/month?year&month` 返回 `{ todos(当月含已完成), overdueTodos(跨月逾期未完成), notes(当月更新未归档) }`；拖拽改期复用 `PUT /api/todos/{id}`（dueDate 已支持）。
> - 前端：新 `CalendarView.vue`（月网格 6×7、周一起始、今日高亮、拖拽改期、格内待办勾选/删除、点击空白格快捷新建、跨月逾期提示条、便签圆点点击跳转）+ `CalendarLayout.vue`（MainLayout 壳 + 面包屑顶栏）；路由 `/calendar` + 页面标题；`navConfig` 新增 `calendar` 项（待办后）。

## 方向二：信息聚合

### ④ RSS 阅读器

**目标**：独立「订阅」页，订阅源管理 + 定时抓取 + 已读/星标 + 一键收藏到收藏夹（与现有收藏打通）。

**后端**
- 新增依赖：`com.rometools:rome`（RSS/Atom 解析；免费开源）
- 新表（启动幂等自建）：
  - `t_feed`：`id / user_id / url / title / site_url / icon / last_fetched_at / fetch_interval_min(默认30) / deleted / create_time / update_time`
  - `t_feed_item`：`id / feed_id / user_id / guid / title / link / author / summary / content / published_at / fetched_at / read_flag / starred / deleted` + 唯一索引 `(feed_id, guid)` 防重复
- 新 `FeedService`：
  - `addFeed(url)` —— 抓取+解析（Rome），提取 title/siteUrl/icon，初始拉取（上限 50 条）
  - `listFeeds()` —— 附带每源未读数
  - `fetchFeed(id)` / `fetchAll()`（`@Scheduled` 每 30 分钟；按 `last_fetched_at + interval` 跳过未到期；串行+间隔防封）
  - `listItems(feedId, filter: unread|starred|all, page)` —— 分页
  - `markRead(itemId)` / `markAllRead(feedId)` / `toggleStar(itemId)`
  - `itemToBookmark(itemId, directoryId)` —— 复用 `BookmarkService.addBookmark`（title/link/icon 直传），打通收藏夹
- `FeedController`：`/api/feeds` CRUD + `/{id}/fetch` + `/{id}/items` + `/items/{id}/read|star` + `/{id}/read-all` + `/items/{id}/to-bookmark` + `GET /api/feeds/unread-total`

**前端**
- 新路由 `/feeds`（MainLayout 壳）→ `FeedsView.vue` 三栏布局：
  - 左：订阅源列表（未读数角标、增删源、手动刷新、全部已读）
  - 中：条目列表（标题/摘要/时间/星标，未读加粗）
  - 右：阅读窗格（全文 content 渲染，打开即标记已读；「收藏到收藏夹」按钮 → 选目录）
- `navConfig.ts`：新增 `feeds` NavKey（Rss 图标，route → /feeds），默认序放音乐后；MobileTabBar 视情况加
- 全局搜索（可选）：加「订阅」组匹配 feed 标题

**验收**：①添加 RSS/Atom 源成功并拉到初始条目；②定时任务按间隔抓新，guid 去重不重复入库；③未读/星标/全部已读/单条已读正确；④一键收藏进收藏夹且可打开；⑤未登录无法访问。

> ✅ 已实施（2026-09-22）：
> - 后端：新增 `com.rometools:rome:2.1.0` 依赖；`FeatureTableInit` 幂等建 `t_feed` / `t_feed_item`（(feed_id,guid) 唯一索引防重）；`Feed` / `FeedItem` 实体 + Mapper；`FeedService`（addFeed 抓取验证+初始 50 条 / listFeeds 带未读 / fetchFeed 手动刷新 / fetchAllScheduled 每 30 分钟按间隔抓取 + RedisLock 防重 + 串行限速 / listItems 分页 / markRead / markAllRead / toggleStar / itemToBookmark 复用 addBookmark 打通收藏夹 / unreadTotal）；`FeedController`（/api/feeds CRUD + items + read/star + read-all + to-bookmark + unread-total，默认登录鉴权）。
> - 前端：新 `FeedsView.vue` 三栏（订阅源列表+未读角标/条目列表+未读加粗+星标/阅读窗格 content 渲染+一键收藏到收藏夹+原文跳转）+ 添加订阅弹窗 + 收藏目录选择；`FeedsLayout.vue`（MainLayout 壳）；路由 `/feeds` + 页面标题；`navConfig` 新增 `feeds` 项（日历后）。
