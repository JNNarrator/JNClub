## 二、M1 · 触屏可用性（P1）

### M1-1 触屏拖拽替代

- 目标：移动端（`pointer: coarse` 或 <768px）保留「拖动归档」，或明确降级为菜单路径。
- 方案（择一，实施时定稿）：
  - **A（推荐，改动小）**：窄屏下不启用 DnD，改由 `⋯` 菜单的「移动到…」承担；对已有菜单入口做可见性确认即可，不新增手势。
  - **B（体验更好）**：用 Pointer Events 实现长按拖拽（`pointerdown` → 300ms 长按 → 跟随手指 → `pointerup` 落到目标目录），复用现有 `useItemDragContext` 的 `setDragging` 载荷与 `FolderTree` 的 drop 逻辑。
- 约束：桌面端 DnD 行为不变；不引入新依赖。

### M1-2 长按唤起菜单

- 在 `useContextMenu.ts` 增加 `openMenuAt(x, y, options, onSelect)`，与现有 `openMenu(e)` 共用状态。
- 新增 `useLongPress`（或内联）为挂 `@contextmenu` 的元素补 `pointerdown/pointerup/pointercancel` 长按（约 500ms，移动超过阈值则取消），调用 `openMenuAt`。
- 覆盖 7 处挂载点；桌面右键行为不变。
- 注意：长按需 `preventDefault` 抑制 iOS 文本选择/呼出系统菜单，但**不能**阻断正常滚动。

### M1-3 hover-only 操作按钮兜底

- `FolderTree.vue` 的 `.node-menu-btn` 增加 `@media (hover: none) { opacity: 1 }`。
- 复查其余「hover 才显形」模式，逐个人工确认（本次审计中 `CollectionGrid/List`、`NoteGrid` 的 `opacity: 0` 属**入场动画初态**，非按钮隐藏，不改）。

## 六、风险与边界

1. **不追求「移动端全覆盖」**：本迭代聚焦可达性与一致性，不为每个组件重做窄屏版式。
2. **原生 DnD 与 Pointer 手势冲突**：长按拖拽必须与页面滚动、文本选择互不干扰，阈值需实测调优。
3. **长按与右键并存**：桌面端走 `contextmenu`，触屏走长按，两者共用菜单状态，避免双开。
4. **断点收敛的回归面**：改动 `MainLayout`/`Home` 的监听方式后，需回归桌面折叠/展开与移动 TabBar 切换。
5. **music-frontend 不在本次范围**：其适配已达标，避免无谓改动引入播放回归。

## 十、审查修复（2026-10-10）

首轮实现后做了一次针对性代码审查（只读），发现并修复以下问题：

| 严重度 | 问题 | 修复 |
| --- | --- | --- |
| 高 | `useLongPress` 的 click 抑制守卫锚在「长按触发时刻」并 600ms 过期：按住超过约 1.1s 再抬手会**漏抑制**（误触发打开书签/预览/切换选中）；而浏览器不派发 click 时又会吞掉用户**下一次**点击（首次点菜单项无反应）。 | 守卫改到 **pointerup 时刻**注册（click 紧随其后派发，可精确覆盖）；新增 `pointerdown` 捕获监听，新手势落下即释放；超时兜底缩短为 400ms。 |
| 中 | 守卫是 document 级无差别拦截，会波及随后弹出的菜单项点击。 | `onCapture` 仅在 `target.contains(ev.target)` 时拦截，菜单等浮层不受影响。 |
| 中 | `timer` / `startX` / `startY` 在 composable 作用域共享，而 `DiskView`、`VaultView` 的 `v-for` 每行复用同一实例，多指同时按下会互相干扰。 | 状态下沉到 `bind()` 内部，每个元素各自独立。 |
| 中 | 长按目标缺少 `user-select` / `-webkit-touch-callout` 兜底：iOS 长按会启动文本选择与 callout，可能派发 `pointercancel` 导致菜单弹不出。 | 新增 `.jnclub-longpress`（`@media (pointer: coarse)` 下禁用选择/callout，`touch-action: manipulation`），并加到 7 个长按元素。 |
| 中 | `:draggable="!isMobile"` 用视口宽度判断能力：<768px 但用鼠标的窗口（分屏/缩放）会失去 HTML5 拖拽。 | 7 个组件改用 `!isCoarse`（指针能力判断）；`MainLayout`、`Home` 的布局判断仍用 `isMobile`。 |
| 低 | 组件卸载只清理触发定时器，click 守卫仍可能在卸载后存活。 | `releaseGuard` 提升到 composable 作用域，`onBeforeUnmount` 一并释放。 |
| 低 | SortableJS 的 `touchStartThreshold: 3` 与长按 `moveThreshold: 10` 重叠：位移 3–10px 时可能同时启动排序并弹出菜单。 | 长按触发时检测 `documentElement.classList.contains('dragging')`，已进入排序则让位（不改动排序阈值）。 |

审查确认无问题的项：`v-on="longPress(...)"` 的对象绑定写法（编译为 `toHandlers`，不会重挂 DOM 监听）；`openMenu` 签名与既有调用方兼容；`MainLayout`/`Home` 迁移首帧正确（`useMediaQuery` 在 setup 期同步求值）；8 处条目卡片的 `:draggable` 在桌面端行为不变。
